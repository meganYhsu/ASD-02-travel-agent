# Shared RAG API Contracts

The Shared RAG service runs locally and provides HTTP endpoints for corpus refresh, context retrieval, and grounded question answering.

Default server: `http://127.0.0.1:7001`

## POST /rag/refresh

Refreshes the shared RAG corpus from the integrated project data sources and rebuilds the ChromaDB vector collection.

### Request

```json
{}
```

### Successful Response

```json
{
  "status": "success",
  "caller": "student",
  "chunk_count": 196,
  "collection": "student_enrolment_enterprise_context",
  "corpus_path": "corpus/corpus.jsonl",
  "vector_store_status": "ready"
}
```

## POST /rag/retrieve

Retrieves the Top-K project context chunks relevant to a query.

### Request

```json
{
  "query": "What activities are planned in Sydney?",
  "k": 5
}
```

### Response

The response contains ranked retrieved chunks including:

- `rank`
- `chunk_id`
- `source_id`
- `authority_tier`
- `text`

Retrieval uses semantic embeddings generated by the local `nomic-embed-text` Ollama model and a ChromaDB vector collection.

## POST /rag/answer

Generates a grounded answer using retrieved project context.

### Request

```json
{
  "query": "What documents are required for travel to Japan?"
}
```

### Successful Response

```json
{
  "status": "success",
  "query": "What documents are required for travel to Japan?",
  "answer": "Grounded answer generated from retrieved context.",
  "citations": [
    {
      "chunk_id": "example-chunk",
      "source_id": "example-source",
      "authority_tier": "tier_1"
    }
  ],
  "confidence_category": "High",
  "retrieval_summary": {
    "k": 5,
    "retrieved_count": 5,
    "top_chunk": "example-chunk"
  }
}
```

Only chunks used to support the generated answer are returned as citations.

If the retrieved context does not provide sufficient evidence, the service returns:

```json
{
  "status": "success",
  "answer": "Insufficient evidence.",
  "citations": [],
  "confidence_category": "Unknown"
}
```

If the local LLM cannot complete generation, the service returns an error rather than presenting the failure as a grounded answer.

## Grounded Answer Contract

The RAG answer must:

1. use only retrieved project context;
2. not introduce unsupported external information;
3. cite only chunks that directly support the answer;
4. provide a confidence category based on supporting evidence;
5. return `Insufficient evidence.` when the retrieved evidence is inadequate.
